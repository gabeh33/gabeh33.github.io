I run a handful of side projects on my Mac mini, each on its own port. I lost track of them, so I built Project Hub: one page on localhost:9999 that lists every project, shows what's running, and has Start and Stop buttons.

Those buttons run shell commands. That makes the hub a juicy target, even though it only listens on 127.0.0.1.

Why 127.0.0.1 isn't a security boundary

Binding to loopback stops other machines from connecting. It does nothing about the browser sitting on the same machine. Any website I visit can tell my browser to send a request to http://localhost:9999. Two attacks fall out of that:

  • CSRF. A page submits a form or fires a fetch() at localhost:9999/api/projects/x/start. The browser sends it. The response is blocked from the attacker by the same-origin policy, but the side effect already happened. If the attacker can also add a project with their own start command, that's remote code execution through my browser.
  • DNS rebinding. An attacker's domain resolves to their server, serves a page, then flips its DNS record to 127.0.0.1. Now the page is talking to my hub while the browser believes it's same-origin, so it can read responses too.

Three checks that close it

1. Allowlist the Host header. Every request must arrive with Host: localhost:9999 or 127.0.0.1:9999. After a rebind, the browser still sends the attacker's hostname, so those requests get a 403. This one check kills DNS rebinding.

def _allowed_host(self):
    return self.headers.get("Host", "") in {
        f"localhost:{PORT}", f"127.0.0.1:{PORT}"}

2. Require a custom header and JSON on every write. Plain HTML forms can't set custom headers or send application/json. A cross-origin fetch() that does either triggers a CORS preflight, and the hub never answers preflights. So a request carrying X-Hub: 1 can only come from the hub's own page.

3. Check Origin when the browser sends one. Belt and suspenders: if an Origin header is present and it isn't the hub itself, reject it.

def _write_ok(self):
    origin = self.headers.get("Origin")
    return (self._allowed_host()
        and self.headers.get("X-Hub") == "1"
        and self.headers.get("Content-Type", "").startswith("application/json")
        and (origin is None or origin in GOOD_ORIGINS))

Testing it

I tested each case with curl before trusting it:

  • A write without X-Hub: 403 forbidden
  • A write with Origin: http://evil.com: 403 forbidden
  • Any request with Host: evil.com:9999: 403 bad host
  • The real page: works

What I'd still watch

This keeps other websites out. It doesn't protect against malware already running as my user, which could just call the API directly. That's an acceptable trade for a personal tool. The bigger risk is me: a tunnel like Tailscale Funnel forwards traffic to localhost, so loopback binding wouldn't stop it, and exposing port 9999 that way would hand anyone a shell. The README says never to do it.

The same pattern applies to any local dev server, agent, or admin panel. If it listens on localhost and does something with side effects, assume a browser tab is going to talk to it.
